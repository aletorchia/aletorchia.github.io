01

Introduzione alla virtualizzazione

VM — Virtual Machine

Le VM sono emulatori di architetture che permettono di far girare un sistema operativo partendo da un file .ISO.

L'hypervisor è il tramite tra sistema operativo e macchina virtuale.

Le VM non sono generalmente utilizzate per il deployment di una singola applicazione perché ogni VM deve eseguire anche un sistema operativo completo, richiedendo quindi più risorse.

02

Tipi di Hypervisor

Gli hypervisor si dividono principalmente in due categorie:

Tipo 1 Bare Metal

L'hypervisor gira direttamente sull'hardware.

Tipo 2 Hosted

L'hypervisor gira sopra un sistema operativo host.

Ring di privilegio

Le architetture x86 aggiungono quattro livelli di privilegio chiamati ring.

  • Ring 0 → Kernel
  • Ring 1 → Device Driver
  • Ring 2 → System Services
  • Ring 3 → User Mode

Più il livello è basso, maggiori sono i privilegi.

Bare Metal

Gli hypervisor bare metal fanno girare le VM come intermediari diretti verso l'hardware.

Un esempio è KVM. 

Hardware fisico
       │
       ▼
Hypervisor Tipo 1
       │
       ├── VM 1 → Guest OS → Applicazioni
       ├── VM 2 → Guest OS → Applicazioni
       └── VM 3 → Guest OS → Applicazioni

Hosted

Gli hypervisor hosted operano all'interno del sistema operativo host e hanno meno privilegi.

Esempi:

  • VMware
  • VirtualBox
Hardware fisico
       │
       ▼
Sistema operativo Host
       │
       ▼
Hypervisor Tipo 2
       │
       ├── VM 1 → Guest OS → Applicazioni
       └── VM 2 → Guest OS → Applicazioni
03

Container

Con i container basta utilizzare un container engine.

Il container engine permette di far girare i container.

Container Engine

  • Docker — scritto in Go
  • Podman

Un container è formato dall'applicazione necessaria e dalle sue dipendenze, come ad esempio le librerie.

I container hanno il vantaggio di funzionare su diversi computer e di fornire un ambiente isolato.

Vantaggi dei container

  • Efficienza → sono più leggeri perché non includono un sistema operativo completo.
  • Velocità
  • Portabilità
  • Riproducibilità → l'ambiente è immutabile e riproducibile.

Architettura Docker

Utente

   ▼

L'immagine è il file che contiene le istruzioni necessarie per creare un container.

Un daemon in ambiente Linux è un servizio che viene eseguito in background.

Da Docker Hub è possibile effettuare il pull di numerosi container e servizi, come NGINX e altri software.

04

Docker Internals

I container sono ambienti isolati dal sistema host.

  • Ogni container vede solamente il proprio file system.
  • Ogni container possiede il proprio stack di rete isolato.
  • Ogni container possiede i propri processi e il proprio PID.
  • I processi dei container sono isolati da quelli del sistema host.
05

Test con NGINX

docker run --name some-nginx \
-v 'C:\Users\path\to\static-website-example:/usr/share/nginx/html:ro' \
-d -p 8080:80 nginx

Cosa significa?

  • --name → assegna un nome al container.
  • -v → effettua un mount tra host e container.
  • -d → esegue il container in background.
  • -p 8080:80 → collega la porta 8080 dell'host alla porta 80 del container.
  • nginx → immagine utilizzata.

Bind Mount

docker run --name some-nginx \
-v '<percorso host>:<percorso container>' \
-d -p 8080:80 nginx

Il percorso dell'host viene scritto prima, seguito dal percorso all'interno del container.

L'opzione :ro indica che il mount è in modalità read only.

Per uscire da un container senza terminarlo:

CTRL + P → CTRL + Q
06

Docker Networking

Il container utilizza una rete virtuale. Il bridge rappresenta il gateway attraverso il quale passa la rete del container.

Tipi di bridge

  • Default bridge → viene creato automaticamente.
  • User defined bridge → viene creato dall'utente e permette anche di gestire il DNS.

Driver di rete

bridge

Rete virtuale privata.

host

Stack di rete condiviso con l'host.

overlay

Unisce più daemon Docker su host differenti.

macvlan

Permette al container di avere un indirizzo MAC proprio.

ipvlan

Permette di assegnare un indirizzo IP al container.

Visualizzare le reti

docker network ls
07

Docker Storage

Docker utilizza principalmente due metodi per gestire i dati persistenti.

Volumes

File system gestito e montato dal Docker Engine.

Bind Mounts

Collegamento tra una cartella dell'host e una cartella del container.

L'opzione utilizzata per entrambi è: 

-v

Visualizzare i volumi

docker volume ls

Struttura di un mount

-v /some/content:/usr/share/nginx/html
  • /some/content → percorso sul computer che esegue Docker.
  • /usr/share/nginx/html → percorso all'interno del container.
  • I due parametri sono separati da :.

Se viene indicato un percorso dell'host si utilizza un Bind Mount.

Se viene indicato il nome di un volume si utilizza un Volume.

Entrare nella bash di un container

docker exec -it <container_id> /bin/bash

# oppure

docker exec -it <container_name> /bin/bash

09

Comandi basilari Docker

docker run hello-world Cerca l'immagine localmente e, se non presente, effettua il pull.
docker ps Mostra i container attualmente in esecuzione.
docker ps -a Mostra tutti i container, anche quelli terminati.
docker exec Esegue un comando all'interno di un container.
docker run Crea un nuovo container.
docker stop <container_id> Ferma un container.
docker start <container_id> Avvia un container fermato.
docker rm <container_id> Rimuove un container.
docker rmi <image> Rimuove un'immagine.
docker attach Permette di collegarsi a un container attivo.
docker detach Permette di scollegarsi senza interrompere il container.
docker inspect <nome_container> Mostra le informazioni dettagliate del container in formato JSON.

Detached e auto-remove

docker run -d --rm
  • -d → esecuzione detached, quindi in background.
  • --rm → elimina automaticamente il container quando termina.

Mapping delle porte

docker run -d -p 8080:8080 kodeklpud/simple-webapp

-p collega la porta dell'host alla porta del container.

Restart policy

--restart unless-stopped

Permette a Docker di provare a riavviare automaticamente il container in caso di crash.

10

Estensioni dei comandi

Opzione Funzione
-i Accesso al canale standard di input.
-t Utilizza un pseudo-terminale.
-e Passa variabili d'ambiente al container.
-d Esegue il container in background.
-v Collega un volume o un mount.
-b Permette di selezionare il driver di rete.
--rm Elimina il container al termine.
-p Mappa una porta host/container.
--name Assegna un nome al container.
--network Collega il container a una rete Docker.
--restart Definisce la politica di riavvio.
11

Comandi Docker e chicche dal server

docker stats

Mostra il consumo di risorse di tutti i container attivi. 

docker stats <id_container>

Mostra il consumo di risorse del container specificato. 

docker stats <nome_container>

Come sopra, ma utilizzando il nome del container. 

docker images

Mostra le immagini presenti localmente.

Il simbolo \ permette di andare a capo nei comandi Docker molto lunghi.

12

Esempi pratici

docker run -itd \
-v dbstore_volume:/dbdata \
--name dbstore \
ubuntu \
/bin/bash

Questo comando avvia un container Ubuntu chiamato dbstore in modalità detached, collegato alla bash del container e con un volume chiamato dbstore_volume montato nella directory /dbdata.
