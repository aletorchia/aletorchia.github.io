01

MySQL

In Linux il database lato server è detto SQLD. MySQLD è un backend in grado di gestire più database.

Dentro MySQL posso quindi gestire più database.

Esempio

  • DBScuola
  • DBAzienda

Entrambi possono essere gestiti dallo stesso SQLD.

Client e server

Per collegarmi al server ho bisogno di un'applicazione Client che si colleghi ad esso.

Il client è un applicativo che permette di interrogare il database.

Tra client e server può esserci anche Internet: non devono essere fisicamente collegati.

Tutto questo vale anche per MariaDB.

Accesso a MySQL

mysql -u root -p
  • -u → specifica l'utente che sta effettuando il login
  • -p → richiede la password dell'utente

Dopo aver effettuato il login ci si ritrova nella CLI di MySQL.

Visualizzare i database

SHOW DATABASES;

Il comando permette di visualizzare i database presenti nel server.

Visualizzare utenti e host

SELECT user, host FROM mysql.user;

Uscire dalla CLI

exit

Il comando exit permette di uscire dalla modalità interattiva del client MySQL senza terminare il container.

Connessione tramite IP

mysql -u root -h 127.0.0.1 -p
  • -u → permette di specificare l'utente
  • -h → permette di specificare l'indirizzo IP
  • -p → richiede la password

Client MySQL

Esistono diversi client che possono collegarsi al server, ad esempio:

  • Estensione MySQL di VS Code
  • MySQL Workbench
  • Altri applicativi compatibili
02

SQL e caratteristiche SQL

SQL è un linguaggio dichiarativo ed è lo standard per la comunicazione con i database relazionali.

  • Definizione dello schema logico
  • Aggiornamento e interrogazione dei dati
  • Gestione della sicurezza del DBMS

Privilegi

L'utente root ha il massimo livello di privilegi.

Modalità di utilizzo

SQL può essere utilizzato in due modi:

  • Modalità interattiva → tramite un interprete di comandi o un'interfaccia grafica che permette di gestire e visualizzare i risultati delle query.
  • Modalità programma → SQL viene utilizzato all'interno di un altro linguaggio, denominato host, ad esempio PHP o Java.

Componenti di SQL

Il linguaggio SQL è formato da tre componenti principali:

DDL Data Definition Language

CREATE, ALTER

DML Data Manipulation Language

SELECT, INSERT, UPDATE, DELETE

DCL Data Control Language

GRANT, DENY, REVOKE

03

Comandi base SQL

CREATE DATABASE

CREATE DATABASE [IF NOT EXISTS] database_name
[CHARACTER SET charset_name]
[COLLATE collation_name];

Le parentesi quadre indicano parametri opzionali.

IF NOT EXISTS permette di creare il database solo se non esiste già, evitando errori.

CREATE TABLE

CREATE TABLE IF NOT EXISTS studenti (
    Matricola MEDIUMINT UNSIGNED NOT NULL AUTO_INCREMENT,
    Cognome VARCHAR(30) NOT NULL,
    Nome VARCHAR(30) NOT NULL,
    DataNascita DATE NOT NULL,
    Genere ENUM('M','F') NOT NULL,
    Nazione VARCHAR(30) NOT NULL DEFAULT 'Italia',
    EMail VARCHAR(50),
    PRIMARY KEY (Matricola),
    UNIQUE KEY CognomeNomeDataN(Cognome, Nome, DataNascita)
) ENGINE=InnoDB;

USE

USE <database>;

Permette di selezionare il database sul quale lavorare.

SHOW TABLES

SHOW TABLES;

Mostra le tabelle presenti nel database selezionato.

DESCRIBE

DESCRIBE <table_name>;

Mostra la struttura della tabella selezionata.

DROP TABLE

DROP TABLE <nome_tabella>;

Elimina la tabella specificata.

INSERT INTO

INSERT INTO studenti
(Cognome, Nome, DataNascita, Genere, Nazione, EMail)
VALUES
('Verdi', 'Alessandro', '2010-02-24',
'M', 'Argentina', 'you@ymail.com');

Permette di inserire dati all'interno della tabella.

SELECT

SELECT <parametri>
FROM <tabella>;

Permette di selezionare i dati desiderati da una tabella.

Se viene utilizzato *, vengono selezionate tutte le colonne.

SHOW CREATE TABLE

SHOW CREATE TABLE studenti\G

Mostra il comando necessario per ricreare la tabella. L'utilizzo di \G permette di visualizzare il risultato in modo più leggibile.

AS

L'operatore AS permette di rinominare temporaneamente una colonna nel risultato. 

SELECT Nome AS 'Nome Studente',
       Cognome,
       DataNascita
FROM studenti;

UPDATE

UPDATE studenti
SET Nazione = 'Argentina'
WHERE Matricola = 232
LIMIT 1;

In questo caso viene modificata la nazionalità di una sola matricola.

DELETE

DELETE FROM studenti
WHERE Matricola = 233
LIMIT 1;

Permette di eliminare un dato dalla tabella.

ALTER TABLE

ALTER TABLE <tabella> ADD <colonna> <tipo>;

ALTER TABLE <tabella> MODIFY <colonna> <tipo>;

ALTER TABLE <tabella> CHANGE COLUMN
<nome originale> <nuovo nome> <tipo>;

ALTER TABLE <tabella> DROP COLUMN <colonna>;

ALTER TABLE <tabella> RENAME TO <nuovo nome>;

Tipi in SQL

  • INT UNSIGNED → permette di utilizzare valori positivi.
  • CHAR(n) → la lunghezza del campo è sempre di n caratteri.
  • VARCHAR(n) → permette di utilizzare campi di lunghezza variabile.
05

Vincoli di Integrità Referenziale

I vincoli di integrità referenziale garantiscono la coerenza dei dati tra tabelle collegate da una relazione.

Concetto chiave

Un vincolo di integrità referenziale impone che ogni valore presente nella colonna di Foreign Key di una tabella figlia corrisponda a un valore esistente nella Primary Key della tabella padre.

Esempio

  • Tabella padre: Studenti
  • Tabella figlia: Assenze
Non è possibile inserire un record in Assenze con Studente = 105 se nella tabella Studenti non esiste un record con Codice = 105.

Sintassi

CONSTRAINT [nome_vincolo]
FOREIGN KEY (colonna_esterna)
REFERENCES tabella_padre (colonna_padre)
[ON DELETE opzione]
[ON UPDATE opzione]

Esempio di tabella figlia

CREATE TABLE Assenze (
    Id INT PRIMARY KEY AUTO_INCREMENT,
    Data DATE NOT NULL,
    Studente INT,

    CONSTRAINT FK_Assenze_Studenti
        FOREIGN KEY (Studente)
        REFERENCES Studenti(Codice)
        ON DELETE RESTRICT
        ON UPDATE CASCADE
);

ON DELETE e ON UPDATE

Opzione Descrizione
CASCADE Modifica o elimina automaticamente i record figli associati.
RESTRICT / NO ACTION Impedisce la modifica o eliminazione del record padre se esistono figli associati.
SET NULL Imposta la Foreign Key a NULL.
SET DEFAULT Imposta la Foreign Key al valore predefinito.

Note tecniche

  1. In MySQL e MariaDB l'integrità referenziale è supportata da InnoDB.
  2. SET DEFAULT non è supportato dal motore InnoDB.
  3. Per l'inserimento bisogna prima inserire i dati nella tabella padre e successivamente nella figlia.
  4. Per la cancellazione manuale si procede al contrario, a meno di utilizzare ON DELETE CASCADE.
06

Le @

@ — Variabile dell'utente

È un contenitore temporaneo creato dall'utente per salvare un valore durante l'esecuzione delle query. 

SET @sconto = 0.20;

@@ — Impostazioni del server

Rappresentano le impostazioni interne di MariaDB che definiscono il comportamento del database. 

SELECT @@max_connections;

SELECT @@time_zone;

Senza @ — Colonna della tabella

Rappresenta il campo reale in cui sono salvati i dati delle righe della tabella. 

SELECT prezzo FROM prodotti;
